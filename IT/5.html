📚 OSIOpen Systems Connection
Теоретическая 7-уровневая модель сетевого взаимодействия
🌐 TCP/IPTransmission Control Protocol / Internet Protocol
Практический стек протоколов — 4 уровня
Уровень OSI TCP/IP Что делает / Примеры
7Прикладной Прикладной Общение приложений: HTTP, SMTP (почта), FTP (файлы)
6Сессионный / 5Представительский — Управление сессией, шифрование, кодирование данных
4Транспортный Транспортный Доставка данных: TCP (надёжный) и UDP (быстрый)
3Сетевой Межсетевой Маршрутизация между сетями (IP-адресация)
2Канальный / 1Физический Канальный (сетевой доступ) Передача по физической среде: Ethernet, Wi-Fi, оптоволокно
💻 Клиент
Устройство, которое запрашивает информацию
🖥️ Сервер
Устройство, которое отдаёт информацию
📡 LAN
Локальная сеть — офис, дом
🌍 WAN
Глобальная сеть — Интернет
🔐 Безопасность / Шифрование
Данные шифруются на сессионном уровне (SSL/TLS), чтобы никто не мог прочитать трафик
💾 СУБДСистема Управления Базами Данных
Программное обеспечение для хранения, изменения и обработки данных — PostgreSQL, MySQL, Oracle, MongoDB
🔑 Токен аутентификации
Цифровой ключ, подтверждающий личность
📜 JWTJSON Web Token
Компактный токен в формате JSON — содержит данные пользователя и подпись
⏳ Короткоживущий токен
Живёт 5–30 минут (Access Token) — повышает безопасность
🔗 OAuth
Протокол, позволяющий войти через соцсеть (Google, VK) без передачи пароля
🏛️ Монолит
Вся логика внутри одной кодовой базы (единый .jar / .exe)
✅ Просто развернуть, ❌ трудно масштабировать
🧩 Микросервисы
Приложение разбито на множество независимых сервисов
✅ Масштабируются по отдельности, ❌ сложное сетевое взаимодействие
🗄️ Database Per Service
У каждого микросервиса своя база данных — изоляция данных
🔌 APIApplication Programming Interface
Правила и способы обмена данными между системами
🔍 Аналогия: официант в ресторане — вы ему заказ (запрос), он приносит блюдо (ответ)
🔗 Endpoint — конкретный URL-адресат, по которому стучатся к API (например, /api/users)
🌍 Открытые (Public)
Доступны всем, нужен API-ключ для связи между серверами (не путать с токеном пользователя)
🤝 Партнёрские
Доступны только проверенным компаниям-партнёрам
🏢 Внутренние
Только внутри компании, не торчат наружу
🧩 Составные (Composite)
Один API, который агрегирует данные из нескольких других API
🛰️ REST API (Representational State Transfer)
Передача самоописываемого состояния — архитектурный стиль для веб-сервисов
🖥️ Клиент-серверная архитектура
  • *Разделение ответственности — UI отдельно, данные отдельно
🚫 Отсутствие состояния (Stateless)
  • *Каждый запрос содержит всю информацию для выполнения — сессии не хранятся на сервере
💾 Кэшируемость
  • *Ответы должны маркироваться как кэшируемые или нет
🧩 Единообразие интерфейса
  • *Стандартные методы: GET, POST, PUT, DELETE
🥞 Слои (Layered System)
  • *Клиент не знает, работает ли он напрямую с сервером или через прокси
📜 Код по требованию (Code on Demand)
  • *Опционально: сервер может передавать клиенту исполняемый код (например, JavaScript)
📄 XMLEXtensible Markup Language
Строгий, многословный формат. Используется в SOAP и старых корпоративных системах
<user><name>John</name></user>
📦 JSONJavaScript Object Notation
Лёгкий, человекочитаемый формат. Используется в 95% современных REST API
{"user": {"name": "John"}}
⚠️ SOAP APISimple Object Access Protocol
SOAP — это строгий протокол, использующий XML и сложные стандарты (WS-Security). Часто используется в банках и госструктурах
✍️ Отличие от REST: REST — это стиль (архитектура), а SOAP — это именно протокол с жёсткими правилами
📊 GraphQL
Язык запросов к API, разработанный Facebook
Отличие от REST: клиент сам решает, какие поля ему нужны — не перекачивает лишние данные 
{ user(id: 1) { name, email } }
— вернёт только имя и почту
🌐 HTTPHyperText Transfer Protocol
Протокол передачи гипертекста — основа веба
🔗 URIUniform Resource Identifier
Идентификатор ресурса — общее понятие
📍 URLUniform Resource Locator
Конкретный адрес ресурса — частный случай URI
🧱 Структура URL
http:// (протокол) + vk.ru (доменное имя) = протокол + домен — это и есть URI / URL
