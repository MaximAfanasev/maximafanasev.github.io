  1. Анализ
  2. Требования
  3. Проектирование
  4. Разработка
  5. Тестирование
  6. Ввод и поддержка
✅ V-Model (верификация / валидация)
  • ➡Левая сторона: Бизнес-требования → Функциональные → Архитектура → Системы → Компонентов
  • ⬅Правая сторона: тестирование каждого уровня
⚡ RADRapid Application Development
Быстрая разработка приложений
🌀 Спиральная модель
Анализ рисков → Разработка → План следующего витка
🧩 Инкремент
Завершённая и полезная часть продукта — готовый кусок функционала
🔄 Итерация
Цикл (временной отрезок) внутри проекта, после которого делают инкремент
🌱 AGILE
  • 👤Люди важнее процессов
  • 📦Продукт важнее документации
  • 🤝Позиция клиента важнее контракта
  • 🔄Готовность к изменениям важнее следования плану
🏉 SCRUM
  • 📆Планирование (Sprint Planning) — что делаем в спринте
  • ☀️Дейли (Daily Scrum) — 15 минут на синхронизацию
  • 🔍Ретроспектива — как мы работали, что улучшить
🎯 Экстремальное программирование (XP)
  • 🧑‍🤝‍🧑Парное программирование — два разработчика за одним экраном
  • 🏢Заказчик рядом (On-site Customer)
  • 🎯Игра в планирование — приоритеты задач
  • 🧪Разработка через тестирование (TDD — сначала тест, потом код)
📉 LSD (Lean Software Development)
  • ✨Бережливая разработка — убираем всё, что не приносит ценности клиенту
  • ✂️Минимизация потерь — лишний код, долгие совещания, перепроизводство фич
⬅️ Shift Left TestingСдвиг влево
Тестирование начинается как можно раньше — на этапе требований и проектирования, чтобы находить баги до написания кода
➡️ Shift Right TestingВ production
Тестирование в production — мониторинг, A/B-тесты на реальных пользователях
