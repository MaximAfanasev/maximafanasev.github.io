🗄️ База данных
Организованное хранилище, позволяющее хранить, изменять, извлекать и удалять данные
📊 Реляционные (SQL)
Табличная структура, строгие схемы, связи между таблицами
Примеры: PostgreSQL, MySQL, Oracle, MS SQL
📦 Нереляционные (NoSQL)
Гибкие структуры (документы, ключ-значение, графы)
Примеры: MongoDB, Redis, Cassandra, Neo4j
🔑 Первичный ключ (Primary Key)
Уникальный идентификатор записи в таблице
Пример: user_id = 1
🔗 Внешний ключ (Foreign Key)
Столбец, который ссылается на первичный ключ другой таблицы (для связи)
Пример: order.user_id → users.user_id
🧩 Нормализация
Декомпозиция (разбиение) БД на логические части для устранения дублирования и аномалий
Цель: правильное проектирование структуры данных
1НФ (каждое поле атомарно) → 2НФ (зависит от всего ключа) → 3НФ (нет транзитивных зависимостей)
⚖️ Балансировщик (Load Balancer)
Распределяет нагрузку между несколькими серверами БД или приложений для повышения производительности и отказоустойчивости
⚡ Redis
Хранилище ключ-значение в оперативной памяти (in-memory). Используется для кэширования, сессий, очередей
📄 JSON-документные
Хранят данные в виде JSON-документов — MongoDB, CouchDB
🕸️ Графовые
Данные в виде узлов (nodes), рёбер (edges) и свойств (properties). Идеально для соцсетей, рекомендаций — Neo4j, ArangoDB
📊 Столбцовые (Columnar)
Данные хранятся по столбцам, а не по строкам. Отлично для аналитики — HBase, Cassandra, ClickHouse
🧩 HBase
Столбцовая БД на основе Hadoop — используется для больших данных (Big Data)
✂️ Партицирование (Partitioning)
Разбиение одной таблицы на части (горизонтальное / вертикальное) внутри одной БД
🌍 Шардирование (Sharding)
Распределение данных по разным серверам — каждый шард отдельная БД
📋 Репликация (Replication)
Создание копий БД на разных серверах
⏳ Асинхронная репликация
Сначала запись в оригинал, потом в реплики — быстрее, но есть риск потери данных
🔒 Синхронная репликация
Запись сразу во все реплики — медленнее, но данные надёжнее

🔬 AtomicityАтомарность
Транзакция выполняется целиком или не выполняется вообще (всё или ничего)
⚖️ ConsistencyСогласованность
Транзакция переводит БД из одного корректного состояния в другое
🔒 IsolationИзоляция
Параллельные транзакции не влияют друг на друга (как будто выполняются по очереди)
💾 DurabilityДолговечность
После фиксации (COMMIT) данные сохраняются даже при сбое
🏗️ DDL — Data Definition Language
Создание и изменение структуры БД
  • *CREATE TABLE — создание таблицы
  • *CREATE USER — создание пользователя
  • *ALTER — модификация структуры (добавить/удалить столбец)
  • *DROP — удаление таблицы / БД
✏️ DML — Data Manipulation Language
Работа с данными внутри таблиц
  • *SELECT — выборка данных
  • *INSERT — вставка новых записей
  • *UPDATE — обновление существующих
  • *DELETE — удаление записей
  • *MERGE — слияние (обновить или вставить)
🔐 DCL — Data Control Language
Права доступа
  • *GRANT — разрешение на операции
  • *REVOKE — отзыв разрешений
  • *DENY — явный запрет
🔄 TCL — Transaction Control Language
Управление транзакциями
  • *BEGIN / COMMIT — объявление и фиксация транзакции
  • *ROLLBACK — откат изменений
📨 Брокеры сообщенийMessage Brokers
Посредник между отправителем и получателем сообщений — Kafka, RabbitMQ, ActiveMQ
📤 Producer
Отправитель — создаёт и отправляет сообщения в топик
📥 Consumer
Потребитель — читает сообщения из топика
📂 Topic
Топик — тема с разделами (категория сообщений)
🧩 Partitions
Разделы — распределение данных внутри топика для параллельной обработки
📍 Offset
Уникальный номер сообщения внутри раздела
📝 ЛогированиеLogging
Запись событий: сбоев, ошибок, подозрительных действий (вид взлома), информационных сообщений
FATAL Тотальный сбой, приложение падает
ERROR Некорректная работа, но приложение живёт
WARN Предупреждение (потенциальная проблема)
INFO Информация о работе приложения (старт, остановка, бизнес-события)
DEBUG Детальная информация для разработчиков (старт/пауза методов)
TRACE Мельчайшая запись процесса (почти каждая строчка кода)
📄 Кэш
Копии страниц/данных для быстрого доступа, хранятся в оперативной памяти
Примеры: Redis, Memcached, CDN
🍪 Куки (Cookies)
Служебные файлы, хранящиеся локально в браузере пользователя
🔐 Сессия (Session)
Данные о пользователе, хранящиеся на сервере (обычно в Redis или БД)
💡 Важно
Куки хранят только ID сессии, а сами данные — на сервере
