1. Жизненный цикл разработки ПО (SDLC)

🔍 Планирование / Анализ
Сбор требований, оценка рисков, составление ТЗ.
🎨 Проектирование и дизайн
Архитектура, UX/UI, выбор технологий.
⚙️ Разработка и тестирование
Написание кода, Unit-тесты, интеграция.
🚀 Деплой
Выкатка на production, настройка окружения.
🛠️ Поддержка и обслуживание
Баг-фиксы, доработки, мониторинг производительности.

2. Артефакты требований

📌 USE CASE (Сценарий использования)
  • Кто использует: Роль пользователя
  • Что хочет: Действие
  • Цель: Результат
  • Шаги: 1. ... 2. ...
  • Описание: Детали сценария
📖 USER STORY (Пользовательская история)
Шаблон «Как [роль], я хочу [действие], чтобы [ценность]»
🧪 TEST CASE (План тестирования)
  • Предусловие: состояние системы
  • Шаги: действия тестировщика
  • Ожидаемый результат: эталонное поведение
  • Постусловие: состояние после теста

3. Структура Технического Задания (ТЗ)

  • Информация о продукте: Назначение, аудитория
  • Глоссарий: Расшифровка терминов
  • Бизнес-требования: Цели компании, KPI
  • Функциональные требования: Что система должна ДЕЛАТЬ
  • Технические требования:
    • Нагрузка: RPS, кол-во пользователей
    • Производительность сервера: CPU/RAM
    • Скорость работы: время ответа API < 200ms
  • Бюджет / Программисты: Стоимость и ресурсы (человеко-часы)

4. INVEST (Качество пользовательских историй)

I Independent — Независимая (не зависит от других)
N Negotiable — Обсуждаемая (можно уточнить)
V Valuable — Ценная (дает пользу бизнесу)
E Estimable — Оцениваемая (понятные трудозатраты)
S Small — Маленькая (входит в спринт)
T Testable — Тестируемая (есть критерии приемки)
🗺️ USM (User Story Mapping): Карта пользовательских историй — визуализация бэклога по оси «Шаги пользователя» (горизонталь) и «Приоритет/версии» (вертикаль).
🚀 MVP (Minimum Viable Product): Минимальная версия продукта с достаточной ценностью для первых пользователей.

5. Типы компиляции

  • Компилируемый: Превращается в машинный код целиком до запуска (C++, Go).
  • Интерпретируемый: Исполняется построчно без компиляции в машинный код (Python, JS).

6. Парадигмы программирования

⚡ Императивная
Описание «КАК» делать (пошаговые инструкции).
📊 Декларативная
Описание «ЧТО» получить (SQL, HTML).
🕰️ Легаси
Устаревший код/система, требующая поддержки, часто без документации.
