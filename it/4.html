1. Модели сетевого взаимодействия

📚 OSI (Open Systems Connection)
Теоретическая эталонная модель из 7 уровней.
🌐 TCP/IP (Transmission Control Protocol / Internet Protocol)
Практический стек протоколов (4 уровня).

2. Базы данных

СУБД (Система Управления Базами Данных) — программное обеспечение для хранения, изменения и обработки данных (PostgreSQL, MySQL, Oracle, MongoDB).

3. Аутентификация и токены

🔑 Токен аутентификации — цифровой ключ, подтверждающий личность.
📜 JWT (JSON Web Token) — компактный токен в формате JSON, содержит данные пользователя и подпись.
⏳ Короткоживущий токен — живёт 5–30 минут (Access Token), повышает безопасность.
🔗 OAuth — протокол, позволяющий войти через соцсеть (Google, VK) без передачи пароля.

4. Архитектура приложений

🏛️ Монолит
Вся логика внутри одной кодовой базы (единый .jar/.exe).
✅ Просто развернуть, ❌ трудно масштабировать.
🧩 Микросервисы
Приложение разбито на множество независимых сервисов.
✅ Масштабируются по отдельности, ❌ сложное сетевое взаимодействие.
🗄️ Database Per Service — у каждого микросервиса своя база данных (изоляция данных).

5. API (Application Programming Interface)

API — это правила и способы обмена данными между системами.
🔍 Аналогия: официант в ресторане — вы ему заказ (запрос), он приносит блюдо (ответ).
🔗 Endpoint — это конкретный URL-адресат, по которому стучатся к API (например, /api/users).

Типы API (по доступности)

🌍 Открытые (Public) — доступны всем, нужен API-ключ для связи между серверами (не путать с токеном пользователя).
🤝 Партнёрские — доступны только проверенным компаниям-партнёрам.
🏢 Внутренние — только внутри компании, не торчат наружу.
🧩 Составные (Composite) — один API, который агрегирует данные из нескольких других API.

6. REST API (Representational State Transfer)

Передача самоописываемого состояния — архитектурный стиль для веб-сервисов.

6 принципов REST (must have):

  • Клиент-серверная архитектура — разделение ответственности (UI отдельно, данные отдельно).
  • Отсутствие состояния (Stateless) — каждый запрос содержит всю информацию для выполнения (сессии не хранятся на сервере).
  • Кэшируемость — ответы должны маркироваться как кэшируемые или нет.
  • Единообразие интерфейса — стандартные методы: GET, POST, PUT, DELETE.
  • Слои (Layered System) — клиент не знает, работает ли он напрямую с сервером или через прокси.
  • Код по требованию (Code on Demand) — опционально: сервер может передавать клиенту исполняемый код (например, JavaScript).

7. Форматы передачи данных

📄 XML (EXtensible Markup Language)
Строгий, многословный формат. Используется в SOAP и старых корпоративных системах.
<user><name>John</name></user>
📦 JSON (JavaScript Object Notation)
Лёгкий, человекочитаемый формат. Используется в 95% современных REST API.
{"user": {"name": "John"}}

8. SOAP API (Simple Object Access Protocol)

⚠️ SOAP — это строгий протокол, использующий XML и сложные стандарты (WS-Security). Часто используется в банках и госструктурах.
✍️ Отличие от REST: REST — это стиль (архитектура), а SOAP — это именно протокол с жёсткими правилами.
