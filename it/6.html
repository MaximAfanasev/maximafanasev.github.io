1. NoSQL — нереляционные базы данных

⚡ Redis — хранилище ключ-значение в оперативной памяти (in-memory). Используется для кэширования, сессий, очередей.
📄 JSON-документные — хранят данные в виде JSON-документов (MongoDB, CouchDB).
🕸️ Графовые — данные в виде узлов (nodes), рёбер (edges) и свойств (properties). Идеально для соцсетей, рекомендаций (Neo4j, ArangoDB).
📊 Столбцовые (Columnar) — данные хранятся по столбцам, а не по строкам. Отлично для аналитики (HBase, Cassandra, ClickHouse).
🧩 HBase — столбцовая БД на основе Hadoop, используется для больших данных (Big Data).

2. Масштабирование баз данных

✂️ Партицирование (Partitioning) — разбиение одной таблицы на части (горизонтальное/вертикальное) внутри одной БД.
🌍 Шардирование (Sharding) — распределение данных по разным серверам (каждый шард — отдельная БД).
📋 Репликация (Replication) — создание копий БД на разных серверах.
⏳ Асинхронная репликация — сначала запись в оригинал, потом в реплики (быстрее, но есть риск потери данных).
🔒 Синхронная репликация — запись сразу во все реплики (медленнее, но данные надёжнее).

4. ACID — свойства транзакций

🔬 Atomicity (Атомарность) — транзакция выполняется целиком или не выполняется вообще (всё или ничего).
⚖️ Consistency (Согласованность) — транзакция переводит БД из одного корректного состояния в другое.
🔒 Isolation (Изоляция) — параллельные транзакции не влияют друг на друга (как будто выполняются по очереди).
💾 Durability (Долговечность) — после фиксации (COMMIT) данные сохраняются даже при сбое.

5. Типы SQL-запросов (4 группы)

DDL — Data Definition Language (определение данных)

🏗️ DDL — создание и изменение структуры БД.
  • CREATE TABLE — создание таблицы
  • CREATE USER — создание пользователя
  • ALTER — модификация структуры (добавить/удалить столбец)
  • DROP — удаление таблицы/БД

DML — Data Manipulation Language (изменение данных)

✏️ DML — работа с данными внутри таблиц.
  • SELECT — выборка данных
  • INSERT — вставка новых записей
  • UPDATE — обновление существующих
  • DELETE — удаление записей
  • MERGE — слияние (обновить или вставить)

DCL — Data Control Language (управление доступом)

🔐 DCL — права доступа.
  • GRANT — разрешение на операции
  • REVOKE — отзыв разрешений
  • DENY — явный запрет

TCL — Transaction Control Language (управление транзакциями)

🔄 TCL — управление транзакциями.
  • BEGIN / COMMIT — объявление и фиксация транзакции
  • ROLLBACK — откат изменений

6. Брокеры сообщений (Message Brokers)

Брокер — посредник между отправителем и получателем сообщений (Kafka, RabbitMQ, ActiveMQ).
📤 Producer (Отправитель) — создаёт и отправляет сообщения в топик.
📥 Consumer (Потребитель) — читает сообщения из топика.
📂 Topic (Топик) — тема с разделами (категория сообщений).
🧩 Partitions (Разделы) — распределение данных внутри топика для параллельной обработки.
📍 Offset — уникальный номер сообщения внутри раздела.

7. Логирование (Logging)

Логирование — запись событий: сбоев, ошибок, подозрительных действий (вид взлома), информационных сообщений.

Уровни логирования (от критичного к детальному)

FATAL
Тотальный сбой, приложение падает
ERROR
Некорректная работа, но приложение живёт
WARN
Предупреждение (потенциальная проблема)
INFO
Информация о работе приложения (старт, остановка, бизнес-события)
DEBUG
Детальная информация для разработчиков (старт/пауза методов)
TRACE
Мельчайшая запись процесса (почти каждая строчка кода)

8. Кэш и хранение состояния

📄 Кэш — копии страниц/данных для быстрого доступа (хранятся в оперативной памяти).
Примеры: Redis, Memcached, CDN
🍪 Куки (Cookies) — служебные файлы, хранящиеся локально в браузере пользователя.
🔐 Сессия (Session) — данные о пользователе, хранящиеся на сервере (обычно в Redis или БД).
Куки хранят только ID сессии, а сами данные — на сервере.
