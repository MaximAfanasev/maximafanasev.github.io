1. GraphQL

📊 GraphQL — язык запросов к API, разработанный Facebook.
Отличие от REST: клиент сам решает, какие поля ему нужны (не перекачивает лишние данные).
Пример: запрос { user(id: 1) { name, email } } — вернёт только имя и почту.

2. Протокол HTTP и адресация

🌐 HTTP (HyperText Transfer Protocol) — протокол передачи гипертекста (основа веба).
🔗 URI (Uniform Resource Identifier) — идентификатор ресурса (общее понятие).
📍 URL (Uniform Resource Locator) — конкретный адрес ресурса (частный случай URI).
Структура URL: http:// (протокол) + vk.ru (доменное имя) = протокол + домен — это и есть URI/URL.

3. Структура HTTP-запроса

GET /api/users HTTP/1.1 ← Start Line (Метод + URI + Версия)
Host: vk.ru ← Заголовки (Headers)
Authorization: Bearer token123 ← Заголовки
Content-Type: application/json ← Заголовки
  ← Пустая строка (Empty Line) — разделитель
{ "name": "John" } ← Тело (Body) — опционально
🚀 Start Line / Request Line — метод, URI, версия HTTP.
📋 Headers — метаданные (тип контента, авторизация, куки).
⬜ Empty Line — разделяет заголовки и тело.
📦 Body — данные запроса (POST/PUT/PATCH).

5. HTTP Методы (полный список)

🔍 GET — запрос данных (без тела).
📄 HEAD — только заголовки (без тела).
🔧 OPTIONS — спрашивает, какие методы поддерживает сервер.
➕ POST — создаёт ресурс (не идемпотентный).
🔄 PUT — полная замена ресурса (идемпотентный).
✏️ PATCH — частичное изменение (не всегда идемпотентный).
🗑️ DELETE — удаляет ресурс (идемпотентный).

6. Идемпотентность и безопасность методов

🔄 Идемпотентный — метод, который можно вызвать несколько раз с одинаковым результатом.
Пример: PUT /users/1 — первый раз создаст, второй раз просто перезапишет (состояние то же).
🛡️ Безопасный — метод не изменяет ресурс на сервере (только читает).
GET, HEAD, OPTIONS — безопасные.

7. HTTP Коды ответа (полный список по вашим записям)

1xx — Информационные

102 Processing — сервер принял запрос, но ещё не завершил обработку (используется для WebDAV).

2xx — Успех

200 OK — запрос успешно выполнен.
201 Created — ресурс создан (обычно POST).

3xx — Перенаправление

301 Moved Permanently — ресурс навсегда перемещён на новый URL.
302 Found — временное перенаправление.

4xx — Ошибка клиента

400 Bad Request — сервер не понимает запрос (невалидные данные).
401 Unauthorized — требуется аутентификация.
403 Forbidden — доступ запрещён (аутентификация есть, но прав нет).
404 Not Found — ресурс не найден.
405 Method Not Allowed — метод не поддерживается для этого ресурса.

5xx — Ошибка сервера

500 Internal Server Error — общая ошибка сервера.
501 Not Implemented — сервер не поддерживает нужную функциональность.
503 Service Unavailable — сервер временно перегружен или на обслуживании.
505 HTTP Version Not Supported — сервер не поддерживает версию HTTP.

8. Базы данных (БД)

База данных — организованное хранилище, позволяющее хранить, изменять, извлекать и удалять данные.
📊 Реляционные (SQL)
Табличная структура, строгие схемы, связи между таблицами.
Примеры: PostgreSQL, MySQL, Oracle, MS SQL
📦 Нереляционные (NoSQL)
Гибкие структуры (документы, ключ-значение, графы).
Примеры: MongoDB, Redis, Cassandra, Neo4j

Ключи в реляционных БД

🔑 Первичный ключ (Primary Key) — уникальный идентификатор записи в таблице.
Пример: user_id = 1
🔗 Внешний ключ (Foreign Key) — столбец, который ссылается на первичный ключ другой таблицы (для связи).
Пример: order.user_id → users.user_id

9. Нормализация БД

🧩 Нормализация — это декомпозиция (разбиение) БД на логические части для устранения дублирования и аномалий.
Цель: правильное проектирование структуры данных.
📌 1НФ (каждое поле атомарно) → 2НФ (зависит от всего ключа) → 3НФ (нет транзитивных зависимостей).
⚖️ Балансировщик (Load Balancer) — распределяет нагрузку между несколькими серверами БД или приложений для повышения производительности и отказоустойчивости.
