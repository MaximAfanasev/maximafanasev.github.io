1. Принципы тестирования (7 принципов)

🐛 1. Наличие дефектов — тестирование показывает наличие дефектов, а не их отсутствие.
⏰ 2. Раннее тестирование — начинать как можно раньше (Shift Left).
📊 3. Скопление дефектов — 80% ошибок сосредоточено в 20% модулей (принцип Парето).
🧪 4. Парадокс пестицида — если повторять одни и те же тесты, они перестают находить новые баги. Нужно встряхивать тестовую базу.
🎯 5. Контекст тестирования — тестирование зависит от контекста (веб-приложение тестируем иначе, чем банковскую систему).
❌ 6. Заблуждение об отсутствии ошибок — если система стабильна, но неудобна пользователям — это плохо. Отсутствие багов ≠ успех.

2. Уровни тестирования (по объёму)

🧩 Модульные (Unit) — тестирование отдельных функций/методов.
🔗 Интеграционные — проверка взаимодействия между модулями.
🏛️ Системные — тестирование всей системы целиком.
✅ Приемочные (Acceptance) — проверка соответствия требованиям заказчика.

3. QA и QC — в чём разница?

🛡️ QA (Quality Assurance) — обеспечение качества. Процессы, стандарты, предотвращение ошибок (проактивный подход).
🔍 QC (Quality Control) — контроль качества. Поиск ошибок в готовом продукте (реактивный подход).

4. Что такое БАГ?

БАГ (Bug) — это любой недостаток / ошибка / действие, которое приводит к:
  • Ошибке (неправильный результат)
  • Сбою (временная проблема)
  • Отказу (постоянный сбой)
  • Недостатку памяти и другим проблемам
Фактический Результат отклоняется от Ожидаемого Результата.

5. Верификация и Валидация (главное отличие)

📋 Верификация (Verification) — проверка соответствия формальным требованиям (документации, спецификации).
👤 Валидация (Validation) — проверка соответствия требованиям пользователя (реальным нуждам).
🎯 Классический пример (ОСЁЛ vs КОНЬ):
🐴 Релиз — ОСЁЛ (непарнокопытное с 4 ногами), а нужен был КОНЬ.
✅ Верификация пройдена — осёл соответствует документации (4 ноги, копыта).
❌ Валидация НЕ пройдена — пользователь хотел коня, а получил осла.

6. STLC (Software Testing Life Cycle)

Жизненный цикл тестирования:
  1. Общее планирование
  2. Уточнение критериев
  3. Уточнение стратегии
  4. Чеклисты
  5. Тест-кейсы
  6. Анализ результатов

7. Тестовая документация

📋 Тест-план — общий план тестирования
📊 Test Strategy — стратегия тестирования
✅ Check list — список проверок (без шагов)
📝 Test case — детальный тест-кейс с шагами
📂 Test suite — набор тест-кейсов
🐛 Баг-репорт — отчёт об ошибке
📈 Test Report — отчёт о результатах
🔗 Traceability Matrix — матрица трассировки (связь требований ↔ тестов ↔ багов)

8. Структура Баг-репорта (полный шаблон)

ID: BUG-12345 // Уникальный идентификатор
Заголовок: Кнопка "Купить" не работает на странице товара
Что произошло: При клике на кнопку ничего не происходит
Где ошибка: Страница /product/123
Когда найден: 2026-09-01 14:30 MSK
Описание ошибки: JS-ошибка в консоли: "Uncaught TypeError"
Автор: Иванова А.
Назначен на: Петров С.
Серьёзность (Severity): Blocker / Critical / Major / Minor / Trivial
Приоритет (Priority): High / Medium / Low
Окружение: Chrome 120, Windows 11
Атрибут дефекта: Функциональный / UI / Производительность
Где воспроизводится: Все окружения / Только Stage
Версия браузера: Chrome 120.0.6099.109
Build: v2.3.1-20260901
Предусловия: Пользователь авторизован, товар в наличии
Шаги воспроизведения: 1. Открыть страницу товара
2. Нажать "Купить"
Ожидаемый результат: Открывается корзина с добавленным товаром
Фактический результат: Ничего не происходит, ошибка в консоли
Вложения: Скриншот, видео, логи
Статус: Open → In Progress → Fixed → Closed / Reopened

9. Виды тестирования (все классификации)

По цели (функциональное vs нефункциональное)

⚡ Функциональное — проверка того, ЧТО делает система.
Альфа / Бета / Модульное / Интеграционное / Системное / Приемочное
⚙️ Нефункциональное — проверка того, КАК система работает.
Нагрузочное / Производительность / Стабильность / Отказоустойчивость / Стресс / Масштабируемость / Безопасность / Совместимость

По важности (глубине)

🔥 Дымовое (Smoke) — проверка критической функциональности (сборка вообще работает?).
🛤️ Критического пути (Sanity) — проверка основных бизнес-сценариев.
🧪 Расширенное (Regression) — полная проверка, чтобы новые изменения не сломали старый функционал.

По характеру

😊 Позитивное — проверка на корректных данных (всё должно работать).
😈 Негативное — проверка на некорректных данных (система должна корректно обрабатывать ошибки).

По доступу к коду

🔓 Белый ящик (White Box) — тестировщик видит код, знает внутреннюю структуру.
⬛ Чёрный ящик (Black Box) — тестировщик не видит код, проверяет только входы и выходы.

10. Специальные виды тестирования

😊 Юзабилити (Usability) — насколько удобно пользователям.
♿ Accessibility — тестирование доступности (для людей с ограниченными возможностями).
⏳ Availability — доступность системы (истекший SSL, низкая скорость интернета).
🌍 Интернационализация — проверка, что продукт можно адаптировать под разные страны.
🗺️ Локализация — проверка конкретной адаптации (перевод, валюта, дата).
